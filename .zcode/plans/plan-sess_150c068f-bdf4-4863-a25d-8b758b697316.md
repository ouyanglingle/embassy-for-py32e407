## 为 embassy-stm32 0.6.0 生成结构图（模块依赖关系）

### 产物

- `D:\embassy-for-py32e407\参考设计\embassy-stm32-0.6.0\embassy-stm32-structure.drawio` —— 源文件，可编辑
- `D:\embassy-for-py32e407\参考设计\embassy-stm32-0.6.0\embassy-stm32-structure.png` —— 预览（无 `-e`）
- 审核通过后用 `-e` 重新导出并 `repair_png.py`，得到可编辑的 `embassy-stm32-structure.drawio.png`

### 选型理由

| 决策 | 选 | 不选 | 理由 |
|---|---|---|---|
| 工具 | `rustimports.py` + `autolayout.py` | 手写 XML / Mermaid | 50+ 模块、用 `#[cfg]` 门控的子模块嵌套，手画不可行；`rustimports.py` 正是 Rust 项目专用 import 图抽取器，输出 autolayout JSON 后由 Graphviz `dot` 自动布局 + 正交连线。 |
| 方向 | LR（左→右） | TB | 模块多而宽，横向能容纳"左侧基础设施 → 右侧外设驱动"的层次；TB 会让图层堆得太长。 |
| 分组 | `--group` | 不分组 | embassy-stm32 大模块都是目录（`rcc/`、`dma/`、`flash/`、`adc/`、`timer/`、`can/`…），`--group` 把每个目录里的子文件框成容器，自动浮现"按芯片家族分文件"的真实结构（例如 `rcc` 容器内嵌套 `f013 / f247 / h / u5` 等），最贴近"结构图"的语义。 |
| 传递约简 | 默认开启 | `--no-reduce` | 不约简的话图里会出现 `A → B → C` 和 `A → C` 的冗余边，对结构图来说反而是噪声；默认开。 |
| 格式 | PNG + `.drawio` | 仅 SVG / 仅 PDF | 用户没指定；PNG 是默认；保留 `.drawio` 方便后续用 draw.io desktop 二次编辑（与本仓库其他可视化资产的习惯一致）。 |

### 执行步骤（落地阶段执行）

1. 工具链就位检查（在 plan 通过后再做）：
   - `python3 --version`、`where tred`、`where dot`、`where drawio` / `draw.io`
   - 缺哪个就退到备用方案（缺 `tred` 则用 `--no-reduce`；缺 drawio CLI 则生成 `.drawio` 源文件 + `encode_drawio_url.py` 浏览器查看链接；缺 dot 则改用 `--layout verticalTree` 或直接交付 JSON/XML）。

2. 抽取 use 图：
   ```
   cd "D:\embassy-for-py32e407\参考设计\embassy-stm32-0.6.0"
   python3 "C:/Users/ouyan/.zcode/skills/drawio-skill/scripts/rustimports.py" . --group --direction LR -o graph.json
   ```

3. 自动布局 + 生成 drawio XML：
   ```
   python3 "C:/Users/ouyan/.zcode/skills/drawio-skill/scripts/autolayout.py" graph.json -o embassy-stm32-structure.drawio
   ```

4. 结构校验（找出悬空边 / 重叠节点 / 重复 id）：
   ```
   python3 "C:/Users/ouyan/.zcode/skills/drawio-skill/scripts/validate.py" embassy-stm32-structure.drawio
   ```

5. 导出预览 PNG（不带 `-e`，避免 vision 拒绝）：

   - 若 `drawio` 可用：
     ```
     drawio -x -f png --width 2000 -o embassy-stm32-structure.png embassy-stm32-structure.drawio
     ```
   - 若仅有 `draw.io`（带点）/ Windows 路径，则换成 `draw.io` 或 `"C:/Program Files/draw.io/draw.io.exe"`。
   - 若 drawio CLI 不可用：用 `encode_drawio_url.py embassy-stm32-structure.drawio` 生成 viewer URL，告诉你浏览器打开。

6. 视觉自检（如果模型支持 vision，最多两轮）：
   - 节点是否重叠 / 出框
   - 边是否堆在一起
   - 标签是否被裁
   - 整体是否表达"模块依赖"语义（应该看到左侧 `time / rcc / dma / gpio / timer` 等核心节点；右侧扇形展开到 `adc / i2c / spi / usart / usb / can / eth / flash / exti / low_power / rtc` 等外设驱动；`interrupt` 由 `_generated` 占位）

7. 给你看预览 PNG → 收反馈 → 必要时改 XML → 重新导出 → 最多 5 轮

8. 最终导出：`-e` + `repair_png.py`，输出 `embassy-stm32-structure.drawio.png`、`embassy-stm32-structure.drawio` 一起交付

### 不在范围内

- 不为 embassy-py32 单独出图（用户没要求）
- 不做模块的"内容简介"标注（结构图只表达依赖，不解释每个模块做什么；解释留给 README）
- 不修改 embassy-stm32 任何源码

### 风险与对策

| 风险 | 应对 |
|---|---|
| `tred` 没装 → transitive reduction 跑不了 | 看到 stderr warning 时，自动回退 `--no-reduce` |
| drawio CLI 不可用 | 走 `encode_drawio_url.py` 浏览器查看，或纯交付 `.drawio` |
| Graphviz `dot` 没装 → autolayout 跑不了 | 改用 `drawio --layout verticalTree`（前提 CLI ≥ v30）；否则尝试 ELK 不行就告知用户安装 graphviz |
| 节点过多（> 80）导致预览 PNG 撞 vision 2576 px 上限 | 已用 `--width 2000` 限制；如仍超，按 `--width 1500` 再试 |
| 用户对布局不满意 | 改 `--direction TB` 重跑 / 改 `--group` / 不用 group / 手改 XML 后 `edgeports.py` 重布边 |

### 完成定义（DoD）

- `.drawio` 源文件存在
- 预览 PNG 可读（不存在节点重叠、标签裁切、出框三类问题中的任何一类；最多容忍 2 处边线轻微交叉）
- `validate.py` 不报"悬空边 / 重叠节点 / 重 id"
- 文件路径在最终回复里以 Markdown 链接给出
