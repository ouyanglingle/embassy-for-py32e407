## PY32E407 HAL 驱动库结构梳理
- 统计了 `Drivers/PY32E407_HAL_Driver`：Inc 85 个 .h（HAL 53 + `py32e4xx_hal.h`，LL 31），Src 76 个 .c（HAL 50 + `py32e407_hal.c`，LL 25）。
- HAL/LL 双全的外设共 28 个；只有 HAL 没有 LL 的 7 个：ESMC、ETH、FDCAN、I2S、IRDA、SCI、SMARTCARD（都是协议栈重的外设）。
- 只有 LL 没有 HAL 的 3 个（基础设施）：ll_bus、ll_system、ll_utils（其中 ll_utils 是 LL 唯一带 .c 的工具实现，LL_mDelay 依赖它）。
- 命名陷阱：HAL 叫 `hal_sd`，LL 叫 `ll_sdmmc`；UART 与 USART 在 PY32E407 是两个独立 IP，两边都成对提供。
- 纯头文件无 .c：LL 侧 bus/cortex/flash/iwdg/system/wwdg；HAL 侧 def/dma_ex/gpio_ex。

## Rust 调用 C 外设库的可行性调研
- 芯片为 **Cortex-M4F**（Makefile: `-mcpu=cortex-m4 -mfpu=fpv4-sp-d16 -mfloat-abi=hard`），Rust target 应为 `thumbv7em-none-eabihf`。
- 链接脚本（Templates/PY32E407xx_Templates/EIDE/py32e407xe.ld）：FLASH 512K @ 0x08000000，RAM 144K @ 0x20000000。
- **重要发现**：固件包 `Drivers/CMSIS/Device/PUYA/PY32E407/Source/` 是空的，但 **SVD 在 Keil DFP 包里**：
  `Pack/KEIL/Puya.PY32E4xx_DFP.1.0.0.pack` → 内部路径 `CMSIS/SVD/PY32E407xx.svd`（约 991 KB，CM4 / FPU / MPU 均标注）。
  同包内还有 `Drivers/CMSIS/Device/PUYA/PY32E4xx/Source/system_py32e4xx.c`。
  → 可用 svd2rust 生成纯 Rust PAC，是绕开 C FFI 的路线。
- GCC 版启动文件：`Templates/PY32E407xx_Templates/EIDE/startup_py32e407xx.s`（EIDE/GCC）；包内自带的 startup 是 armclang 版（Source/ARM/）。
  `Templates/PY32E407xx_Templates/Src/` 下有 `system_py32e407.c`、`py32e407_it.c`、`py32e407_hal_msp.c`、`Inc/py32e407_hal_conf.h`。
- 官方 Makefile 用 `-lc -lm -lnosys -specs=nano.specs`（newlib-nano），Rust no_std 侧需评估是否需要补 libc。
