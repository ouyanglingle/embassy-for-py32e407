# 2026-09-19

## 新建 `cbind-demo`：用 py32e407cbind-rs 走正常启动流程 + PC3 每 1ms 翻转

### 交付物（全新独立 cargo 包 `D:\embassy-for-py32e407\cbind-demo\`）
- `Cargo.toml`：依赖 `py32e407cbind-rs`(path) + `py32e407-pac`(features=["rt"]) +
  `cortex-m-rt 0.7.5` + `cortex-m 0.7.7`(features=["critical-section-single-core"]) +
  `defmt 0.3` / `defmt-rtt 0.4`
- `build.rs`：`--nmagic` + `-Tlink.x` + `-Tdefmt.x`（照抄 demo-py32，不要在 rustflags 重复给）
- `memory.x`：FLASH 512K @0x0800_0000、RAM 144K @0x2000_0000（照抄 demo-py32）
- `.cargo/config.toml`：target `thumbv7em-none-eabihf`、
  runner `probe-rs run --chip-description-path ../demo-py32/PY32E4_Series.yaml --chip PY32E407xE`、
  `DEFMT_LOG=info`
- `src/main.rs`：启动流程分 6 步（见下）+ 主循环

### 启动流程（`src/main.rs`）
0. 复位交给 cortex-m-rt（SP/VTOR/.data/.bss/FPU）
1. `pwr_high_voltage()`：APB1ENR1.PWREN=1 → PWR.CR1 的 VOS=0/SRAM_RETV=0 → PWREN=0
   （= 官方 `SystemInit()`；**PY32 的 PWR 挂 APB1，不是 STM32F4 的 APB1ENR**）
2. `configure_system_clock()`：`LL_PLL_ConfigSystemClock_HSE(8_000_000, HSEBYPASS_OFF, …)`
   → HSE 8MHz ×21 ÷1 = 168MHz，AHB/1、APB1&2 /2 → PCLK 84MHz
3. `setup_1ms_tick()`：`LL_RCC_GetSystemClocksFreq` 读回真值 → `LL_SetSystemCoreClock`
   + `LL_Init1msTick(HCLK)`
4. `pc3_output_init()`：PAC 置 `RCC.AHB2ENR.IOPCEN`（bit4）→ `LL_GPIO_StructInit` +
   `LL_GPIO_Init(pac::Gpioc::PTR as *mut GpioType, …)`，Pin=LL_GPIO_PIN_3、Mode=OUTPUT、
   Speed=LOW、OutputType=PUSHPULL、Pull=NO
5. 主循环：`pc3_set()`（PAC 写 `BSRR.BS3` / `BRR.BR3`）→ 翻 `high` → `LL_mDelay(1)`
   ⇒ 高/低各 1ms = 2ms 周期 **500 Hz 方波**

### 关键结论：cbind 库的「可链接 / 不可链接」边界（本轮核心）
`LL_GPIO_SetOutputPin/ResetOutputPin/TogglePin`、`LL_AHB2_GRP1_EnableClock`、
所有 RCC 配置函数（`HSE_Enable`/`SetSysClkSource`/`SetAHBPrescaler`/`PLL_Enable`…）
在 LL 头里都是 **`__STATIC_INLINE`** → bindgen 会生成声明但 **`.a` 里没有，链接必挂**。
用 `arm-none-eabi-nm --defined-only <out>/libpy32e407_ll.a` 核对真正可用的（大写 T）：
- GPIO：`LL_GPIO_Init` / `LL_GPIO_DeInit` / `LL_GPIO_StructInit`
- RCC：`LL_RCC_GetSystemClocksFreq` + 各 `LL_RCC_Get*ClockFreq` / `LL_RCC_DeInit`
- utils：**`LL_PLL_ConfigSystemClock_HSE` / `_HSI`**（= 官方整套时钟树配置，一条调用搞定）、
  `LL_SetFlashLatency` / `LL_SetSystemCoreClock` / `LL_Init1msTick` / `LL_mDelay`
⇒ 结论：时钟树/时基/延时/GPIO 初始化全走 cbind；**只有"使能 GPIOC 时钟"和"翻转引脚"
这两处 inline 改用 PAC 点寄存器**（内容与 inline 实现逐位一致）。

### 链接期必须由 bin 提供的符号（`nm -u` 查出）
`libpy32e407_ll.a` 引用但不含：`SystemCoreClock`(utils/rcc.o)、`AHBPrescTable[16]`、
`APBPrescTable[8]`（官方定义在 `system_py32e407.c`，而 cbind-rs 只编 `py32e407_ll_*.c`）。
在 main.rs 里用 `#[no_mangle] pub static mut SystemCoreClock: u32 = 16_000_000;` +
`#[no_mangle] pub static AHBPrescTable: [u8;16]=[0,0,0,0,0,0,0,0,1,2,3,4,6,7,8,9];` +
`APBPrescTable: [u8;8]=[0,0,0,0,1,2,3,4];` 补齐。`__aeabi_uldivmod` 由 compiler_builtins 提供。

### 两个必踩的坑
1. **`ErrorStatus` 极性与经典 STM32 相反**：`py32e4xx.h` 里是
   `typedef enum { SUCCESS = 0U, ERROR = !SUCCESS } ErrorStatus;` → **0 = 成功**。
   别按 STM32 的 `ERROR=0` 写判断。
2. **`LL_UTILS_PLLInitTypeDef.PLLMul` 是原始倍频数（2~257）**，不是枚举位域；
   `LL_RCC_PLL_SetMulFactor` 内部写的是 `PLLMul - 2`。其余字段用
   `LL_RCC_HSE_PREDIV_DIV_1` / `LL_RCC_PREDIV_DIV_1` / `LL_RCC_POSTDIV_DIV_1`（都=0）、
   `LL_RCC_SYSCLK_DIV_1`(=0) / `LL_RCC_APB1_DIV_2`(=1024) / `LL_RCC_APB2_DIV_2`(=8192)。

### 链接失败 `_critical_section_1_0_acquire` / `_release`
`defmt-rtt` 内部用 critical-section 做日志互斥 → 必须给一个实现：
`cortex-m = { version="0.7.7", features=["critical-section-single-core"] }`（demo-py32 同样）。

### 有意省略
官方 `SystemInit()` 里那段 `GPIOF` + `FLASH_OPTR2.NRST_MODE` 握手等待（`IOPFEN` 置位→等→复位）
**故意没写**：只在 NRST 被选项字节配成 GPIO 时才真的会等，embassy-py32 同样没有且实机可用。
已在 main.rs 注释里标明"板子改过 NRST 选项字节再补"。

## 追问澄清：PAC 不是硬需求（用户问「一定要用 svd2rust 的 PAC 么」）

结论：**不是必须**。真正不可绕过的约束是「cbind-rs 当前只导出 `.c` 里定义的函数」，
PAC 只是工作区里现成的、唯一能写寄存器的层。想彻底去掉 PAC 有三条路（按推荐度）：
1. **`bindgen::Builder::wrap_static_fns(true)` + `wrap_static_fns_path()`**（需 bindgen 的
   `experimental` feature）：为每个 `static inline` 自动生成非 inline 的 C 包装函数并编进
   `.a`，之后 `LL_GPIO_TogglePin` / `LL_AHB2_GRP1_EnableClock` / 全部 RCC 配置函数都能直接
   FFI。**代价**：要改 `py32e407cbind-rs/build.rs`（不是 demo 侧）、`.a` 变大、绑定数量与
   编译时间显著上升。
2. **自写 `shim.c`**（十几行）：只包装实际用到的那几个 inline，塞进 cbind-rs 或 demo 自己的
   build.rs 里 `cc` 编译。
3. **手写 `#[repr(C)]` 寄存器结构体**：等于自己维护一份迷你 PAC，最轻但容易错、没类型检查。

用 PAC 的实际代价很小：整个 demo 只用它做了 **2 处寄存器写**（`RCC.AHB2ENR.IOPCEN`、
`GPIO.BSRR/BRR`）。时钟树 / 1ms 时基 / 延时 / GPIO 配置**本来就已经是纯 LL 调用了**。
保留 PAC 的收益：位域名有编译期检查、IDE 可跳转、不需要动 cbind-rs。
