## 新建 `temp_pac_demo/` —— 仅用 PAC 翻转 PC3 的最小示例

- 仓库里第三条「PC3 翻转」路线：跟 `demo-py32`（embassy-py32 HAL）和 `cbind-demo`（cbind-rs FFI）对比
- **只依赖** `py32e407-pac`（仅开 `rt` feature）+ `cortex-m-rt`；不引入 embassy-py32、cbind-rs、cortex-m
- 关键写法：
  - `Peripherals::steal()` 而不是 `take()` —— 不开 `critical-section` feature，避免引入 cortex-m 的
    `critical-section-single-core` 实现
  - `dp.rcc.ahb2enr().modify(|_, w| w.iopcen().set_bit())` —— svd2rust 已把 `IOPCEN` 拆成字段
  - `dp.gpioc.moder().modify(|_, w| unsafe { w.moder3().bits(0b01) })` —— `bits()` 在 svd2rust 0.37 是 unsafe
  - `dp.gpioc.bsrr().write(|w| w.bs3().set_bit())` / `.br3()` —— 原子翻转
- 1ms 软件忙等（HSI16 @ 16 MHz）—— 不开 SysTick、不开 PLL
- `cargo check --target thumbv7em-none-eabihf` 通过；`cargo build --release` 生成 ELF，
  符号表验证：Reset@0x08000198、main@0x08000234、_stack_start@0x20024000（144K RAM）
- `.cargo/config.toml` 复用 demo-py32 的 `PY32E4_Series.yaml`（`--chip-description-path ../demo-py32/...`）
- 路上踩到的坑（已记到 MEMORY.md）：
  - PAC 字段是小写（`rcc`/`gpioc`），不是大写
  - `FieldWriter::bits()` 在 svd2rust 0.37 是 unsafe
  - `take()` 在不开 feature 时不编译，必须用 `steal()`

## 把 temp_pac_demo 升级到 embassy-executor 异步版本

- 关键变化：`#[entry] fn main() -> ! { loop {} }` → `#[embassy_executor::main] async fn main(spawner)`
- 引入了 4 个新 crate：`embassy-executor = "0.10"`（`platform-cortex-m` + `executor-thread`）、
  `embassy-time = "0.5"`（`tick-hz-1_000` + `generic-queue-8`）、`embassy-time-driver = "0.2"`、
  `embassy-time-queue-utils = "0.3"`，外加 `critical-section = "1.1"`（注意要显式列出来
  —— 即使它是 embassy-* 的传递依赖，`use critical_section::...` 也得直接声明）
- 时基：自己写了 `src/time_driver.rs`，用 SysTick @ 1 kHz + `embassy-time-queue-utils::Queue`（heapless::Vec<{at, Waker}>，容量 8）当软定时器。**周期扫描模式**（每 tick 检查队列唤醒到期 waker），不是 tickless
- 裸金属版本在 hot loop 里调 `delay_ms(1)`，CPU 100% 占；新版 `Timer::after(...).await` 让 executor 进入 WFE，SysTick 唤醒后才返回 —— **CPU 真正空闲**

### 路上踩到的坑

1. **`core::sync::atomic::AtomicU64` 在 thumbv7em-none-eabihf 上根本没定义**。
   Cortex-M4F 最大支持 32-bit atomic（LDREX/STREX），LDREXD/STREXD 不通用。
   改用 `critical_section::Mutex<RefCell<u64>>` 包 `TICK_COUNT`：
   读 / 写都在 critical section 里，串行化避免 8 字节读撕裂。
2. **`#[embassy_executor::task] async fn f()` 默认 pool_size = 1**。再 spawn 第二次同函数 → `SpawnError`。
   `spawner.spawn(blink())` 的 `blink()` 返回 `Result<SpawnToken, SpawnError>`，先 `.unwrap()` 再喂给 `spawner.spawn(token)`（spawner.spawn 不返回 Result）。
3. **`#[embassy_executor::main]` 不需要自己加 `#[entry]`**：宏展开时自动加 `#[cortex_m_rt::entry]`。
4. **SysTick 必须自己写 `#[cortex_m_rt::exception] fn SysTick()`**：cortex-m-rt 的 default 默认 handler 会让 SysTick 触发时进 spinloop —— 没 time driver 的 ISR，队列永远不会被推进，`Timer::after().await` 永远醒不来。

## size 字段含义（Py32E407 / 任何 Cortex-M）

- `text` = `.text + .rodata`（实测 cargo size 把 vector_table 也算进去）：
  最终**烧进 flash** 的总量 = `.vector_table + .text + .rodata + .data`
- `data` = `.data`（带初值的全局变量，烧 flash，运行时复制到 RAM）
- `bss` = `.bss + .uninit`（零初始化，**只占 RAM，不占 flash**）
- 因此：**flash 用量 = text + data**，**RAM 用量 = data + bss**

## embassy 在 PAC-only 工程上的最小骨架（已验证可 build）

```toml
# Cargo.toml
[dependencies]
py32e407-pac = { path = "../py32e407-pac", features = ["rt"] }   # 注意：不要开 critical-section
cortex-m-rt = "0.7.5"
cortex-m = { version = "0.7", features = ["critical-section-single-core"] }
embassy-executor = { version = "0.10", features = ["platform-cortex-m", "executor-thread"] }
embassy-time = { version = "0.5", features = ["tick-hz-1_000", "generic-queue-8"] }
embassy-time-driver = "0.2"
embassy-time-queue-utils = "0.3"
critical-section = "1.1"   # 必须显式声明，否则 use 不到
```

```rust
// src/main.rs —— 不要 #[entry]、不要 fn main() -> !
#[embassy_executor::main]
async fn main(spawner: Spawner) {
    // init 外设、time driver、spawn 子任务，然后 return ()
    spawner.spawn(blink().unwrap());   // blink() -> Result<SpawnToken, _>
}

#[embassy_executor::task]
async fn blink() {
    loop {
        do_thing();
        Timer::after(Duration::from_millis(500)).await;  // 真正让出 CPU
    }
}

#[cortex_m_rt::exception]
fn SysTick() { /* 推 TICK_COUNT + 检查 embassy queue 唤醒 */ }
```
