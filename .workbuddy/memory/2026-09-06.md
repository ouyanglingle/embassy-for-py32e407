## 生成 PY32E407 PAC 库

- 源 SVD：`参考设计/PY32E407_Firmware_V0.7.0/Pack/KEIL/CMSIS/SVD/PY32E407xx.svd`（device PY32E407xx，内核 CM4，NVIC_PRIO_BITS=4，86 个中断）
- 产出目录：`D:\embassy-for-py32e407\py32e407-pac`（与 `embassy-py32`、`demo-py32` 同级）
- 工具链：svd2rust 0.37.1 + form 0.13.0 + rustfmt，edition 2021，target 默认 `thumbv7em-none-eabihf`
- 关键流程（踩坑记录）：
  1. `svd2rust -i X.svd --target cortex-m --edition 2021 -o src` 会把 `build.rs`、`device.x` 也生成到 src/ 下，需移到 crate 根目录（build.rs 的 `include_bytes!("device.x")` 相对根目录）
  2. `form -i src/lib.rs -o src/` 后再 `rm src/lib.rs`，lib.rs 骨架会丢失，需重建：先备份完整 lib.rs → rustfmt 格式化 → 按顶层 `pub mod NAME {` 括号配平替换成 `pub mod NAME;`
  3. svd2rust 0.37 生成代码仍依赖 `vcell`（generic.rs 中 VolatileCell），Cargo.toml 必须加 `vcell = "0.1.3"`，否则 E0433
  4. 依赖：cortex-m 0.7（必选）、cortex-m-rt 0.7（feature rt）、critical-section 1.x（feature critical-section）
- 验证：`cargo build` 与 `cargo build --features rt,critical-section` 均通过
- 遗留：PAC 不含 memory.x（Flash/RAM 布局未知）；Cortex-M4 是否带 FPU 待确认，若无 FPU 需把 target 改为 thumbv7m-none-eabi

## demo-py32 点灯 Demo

- 用补丁版 PAC 写了最小 blink demo：RCC.AHB2ENR.IOPAEN 开时钟 → GPIOA.MODER5 输出 → BSRR 原子翻转，SysTick（HSI=16MHz）毫秒延时
- 文件：`demo-py32/{Cargo.toml, .cargo/config.toml, memory.x, src/main.rs}`，target `thumbv7em-none-eabihf`
- 踩坑 1：cortex-m-rt 未开 `device` feature 会生成兜底 `__INTERRUPTS`，与 PAC 冲突 → PAC Cargo.toml `rt = ["dep:cortex-m-rt", "cortex-m-rt?/device"]`
- 踩坑 2：cortex-m 0.7.x 单核 critical-section 实现 feature 名是 `critical-section-single-core`（不是 `critical-section`），否则链接报 `_critical_section_1_0_acquire` 未定义
- 踩坑 3：svd2rust 0.37 对无枚举值的多 bit 字段，`variant()` 需 `IsEnum`，需用 `unsafe { w.field().bits(v) }`
- SVD 补丁版 PAC 修复后：rt feature 改为联动 cortex-m-rt/device，已重新验证 demo 编译通过（release 占用 Flash 328B / RAM 0）
- PY32E407 内存布局：Flash 512K@0x08000000；SRAM1 96K + SRAM2 16K 连续@0x20000000；CCMSRAM 32K@0x10000000；HSI=16MHz
