## demo-py32 改 HSE+PLL 168MHz 后启动失败：Timeout 诊断（2026-09-14 上午）

- 现象：用户按 PY32Studio 生成的 C 工程（`C:\OH\oh-my-files\...\PY32E407_files\demo`）把 demo-py32 改成
  HSE 走 PLL，`cargo run` 后 `rcc: clock init failed: Timeout`（lib.rs:114）。
- 已核实的关键事实：
  - PY32Studio 工程 `Core/SRC/rcc.c::Studio_RCC_Init`（**用户指定的权威依据**）：HSE ON、
    `HSEFreq=RCC_HSE_4_8MHz`（4~8MHz 驱动档）、PLL src=HSE、`PLLMUL=168`、`PREDIV=DIV8`、`POSTDIV=DIV1`；
    SYSCLK=PLL、AHB/1、APB1/4、APB2/2、FlashLatency=7；USB 时钟用 HSI48。
  - 用户 Rust `enable168mhz()` 原值：HSE 8MHz、`HseMode::Oscillator`、`HseDrive::Medium`；PLL HSE、/8、×168、/1。
  - rcc.rs 的 `HseDrive` 编码与 LL 一致（Low=0=4-8M、Medium=1=8-16M、High=2=16-32M）——**不是编码 bug**。
  - 已核对 HAL 的 HSE 使能序列（关HSE→等HSERDY=0→写HSEDRV→开HSE→等HSERDY）；rcc.rs 顺序一致，无其它差异。
- ⚠️ **走过的弯路（教训）**：曾据 studio 工程 `Core/SRC/system_py32e407.c` 的 `HSE_VALUE=24000000` 判板载 24MHz，
  并改成 24MHz 配置——**错**。用户明确板子就是 **8MHz**，且要求以 studio 的 `rcc.c` 时钟配置为准。
  → **studio/CMSIS 的 `HSE_VALUE` 是模板默认值，不能当作板载晶振真值**；晶振应以用户实际选定的 `HSEFreq` 为准。
- 结论：**studio 配置与用户 Rust 逐项对照，唯一差别是 HSE 驱动档**（studio 4~8MHz vs 用户 Medium 8~16MHz）。
- 改动 1：`embassy-py32/src/rcc.rs` 的 `Error::Timeout` 拆成 **`HseNotReady` / `PllNotReady` / `SysclkSwitchTimeout`**。
- 改动 2：`enable168mhz()` → `freq=8MHz, drive=HseDrive::Low`，PLL 保持 DIV8/168/DIV1（=168MHz）。release 0 error 0 warning。
- 若仍失败，按新错误码定位：`HseNotReady`→晶振未起振/驱动档；`PllNotReady`→PLL 参数。

### 实测收敛（关键）
- 实测 A 版（24MHz 字段/High/`DIV1×7`）**能运行**；B 版（8MHz/Low/`DIV8×168`）→ **`PllNotReady`**。
  → `PllNotReady` 说明 HSE 那步已过、**卡在 PLL 锁定**；驱动档是红鲱鱼（已被错误码排除）。
- 两次失败的配置（用户原版、B 版）共同点 = **PREDIV=DIV8**；能跑的 A 版是 **PREDIV=DIV1**。
  → 判为 PLL 参考频率过低：8MHz/8 = **1MHz < DS 表5-22 的 PLL 输入下限 2MHz** → 不锁定。
  （studio 生成的 `PLLPREDIV=DIV8` 本身就是无效配置，用户照抄也因此失败。）
- 已核对 PAC `CFGR3` 字段位：PLLSRC bit0 / PLLXTPRE bit1 / PLLPREDIV 2:3 / PLLPOSTDIV 4:5 /
  PLLFBDIV 8:15 / PLLCPGAIN 16:19 —— rcc.rs 的写入与编码均正确；HAL 与 rcc.rs 都不写 PLLCPGAIN，非差异点。
- **最终修正**：`freq=8MHz, drive=HseDrive::Low, PLL prediv=DIV1, mul=21`（ref=8MHz ∈2-32，输出 168MHz ∈24-170）。
  release 0 error 0 warning。
- **二选一判定**：若这版能起 168MHz → 确认晶振 8MHz；若仍 `PllNotReady` → 晶振实为 24MHz（应改 `freq=24MHz` + `DIV1×7`）。
